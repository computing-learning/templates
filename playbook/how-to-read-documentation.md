# How to Read Technical Documentation

## Goal

Extract useful technical knowledge without reading every documentation page sequentially.

---

# First Pass — Navigation

Do not study deeply during the first pass.

Identify:

* Purpose
* Major concepts
* Architecture
* Quick start
* Configuration
* Operational behavior
* Failure handling

The objective is to understand the structure of the documentation and determine where important information lives.

---

# Second Pass — Questions

Read documentation to answer specific questions rather than reading passively.

Examples:

* What problem does this tool solve?
* What guarantees does it provide?
* What guarantees does it not provide?
* What is the default behavior?
* What happens during failure?
* What are the operational limits?

Turn unanswered questions into learning backlog items instead of interrupting the current reading flow.

---

# Third Pass — Verification

Verify important concepts through experimentation.

Perform at least these actions:

```text
Run a small example
        ↓
Change one setting
        ↓
Cause one failure
        ↓
Observe the result
```

Compare the observed behavior with your understanding from the documentation.

If they differ, investigate why.

---

# Output

After reading the documentation, create:

* Topic note
* Keyword backlog
* Cheat sheet
* Lab idea
* Unanswered questions

The goal is not to remember the documentation itself.

The goal is to convert documentation into knowledge that can later be recalled, practiced, and applied.

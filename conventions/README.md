## Purpose

These conventions define the shared standards used across every repository in the `computing-learning` organization.

Following these conventions ensures that repositories remain:

* Consistent
* Predictable
* Searchable
* Easy to navigate
* Easy to automate
* Easy to maintain

---

## Covered Areas

The convention documents define standards for:

* Naming
* Repository structure
* Curriculum metadata
* Documentation style
* Topic lifecycle and status
* Spaced repetition
* Learner progress separation

---

## Design Principles

Every repository should follow the same fundamental principles:

* One consistent structure.
* One consistent naming scheme.
* One documentation style.
* Stable topic identifiers.
* Machine-readable metadata.
* Separation between curriculum and learner data.
* Reproducible learning workflows.

---

## Scope

These conventions apply to all repositories within the `computing-learning` organization, including:

* Technical knowledge repositories
* Architecture repositories
* Programming language repositories
* Database repositories
* Distributed systems repositories
* AI and machine learning repositories
* Future learning repositories

---

## Non-goals

These conventions do **not** prescribe:

* Which technologies should be learned.
* The order in which topics must be studied.
* Personal learning schedules.
* Individual learner progress.

Those decisions belong to roadmap documents and learner-specific tools.

---

## Evolution

The conventions are intended to evolve over time.

Changes should preserve backward compatibility whenever practical and maintain a consistent experience across all repositories in the organization.
